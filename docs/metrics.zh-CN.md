# 统计口径

[English](metrics.md) · [简体中文](metrics.zh-CN.md) · [README](../README.zh-CN.md)

## 正文均速

界面读取 `PerformanceHistory.view(...).bodyAverage`，菜单栏与面板对同一个值四舍五入为整数。

1. 按会话、模型、推理档位分组。
2. 从 `token_usage_record` 读取每次请求的官方输出和推理 token。
3. 排除生成了 `function_call` 或 `custom_tool_call` 的请求。只扣推理仍会留下工具参数 token，因此不能直接当作正文。
4. 要求预期生成项具有完整、有效的计时；缺失或不一致时不拿订阅时间补算。
5. 对每次请求内的 `AgentMessage` 区间取并集。分母不包含推理项或工具执行区间。
6. 选择最近五个有效请求，用合计正文 token（输出减推理）除以合计正文区间秒数。

例如，两个有效请求分别为 200 token / 4 秒、600 token / 20 秒，则合计为 `800 / 24 ≈ 33 tok/s`，不是 50 与 30 的算术平均。

这些区间表示客户端可见的消息生命周期，不能分离网络延迟，也不等于服务端从首 token 到末 token 的解码区间。缺失或被筛除的请求还会带来样本选择偏差。它适合谨慎观察近期正文到达速度，不能衡量模型整体能力。

样本在空闲、重启和工具执行期间保留。面板显示实际样本数和最新样本完成时间。更换模型或档位后使用对应分组；该组已有的旧样本仍可被使用，没有按时间自动过期。

## 轮次计时

一次**请求**是一条模型响应；一**轮**对应一次用户轮次的工作，可能包含多次模型请求和工具调用。

- 进行中的耗时使用可取得的轮次开始时间。
- 完成后的耗时读取官方 `task_complete.duration_ms / 1000`。
- 首 token 延迟读取官方 `time_to_first_token_ms / 1000`；它不是思考耗时，也不是平均请求延迟。
- 整轮完成时间包含最终回答输出。若 Codex 的界面标签截止于最终回答开始，数字会更小；不能默认两个标签的终点相同。
- 不足一分钟时显示一位小数；超过一分钟时截断为整分、整秒。
- 工具累计是已记录工具项时长之和，可能并行或嵌套，不能直接从整轮耗时中减掉它来求思考时间。

## 官方用量

每轮完整的 `turn_token_usage` 替换旧值，不重复累加；请求 ID 用于去重。会话累计优先采用 `thread_token_usage`，避免被旧 `token_count` 汇总覆盖。

缓存输入已包含在输入里，推理已包含在输出里，不再额外相加。缓存命中率在同一轮内计算，输入为零或未知时不显示。上下文采用最新请求总量与已报告上下文窗口，不使用会话累计。

## 未知值与断线

缺失指标会隐藏或说明等待上报，不伪造为零。记录中确实为零的工具时长，或舍入后很小的值，仍可能显示 `0.0秒`。历史加载期间可继续显示已恢复样本；重连时快照和补发文本只恢复状态，不产生虚假的实时 token 峰值。

基于本地 tokenizer 的三秒可见文本计数仍用于内部诊断，不是菜单栏保留的平均速度。当前界面不提供无法可靠测量的思考均速或思考与正文综合均速。
